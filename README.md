## Изменяемые и неизменяемые объекты

### Изменяемые объекты (передача по ссылке):

list, dict, set, bytearray

### Неизменяемые объекты (передача по значению):
- int, float, complex, string,
- tuple (значение неизменяемого объекта не может измениться, но его составляющие — могут),
- frozenset [неизменяемая версия set],
- bytes

### Особенности:

- Python обрабатывает изменяемые и неизменяемые объекты по-разному.
- Доступ к неизменяемым объектам быстрее, чем к изменяемым.
- Изменяемые объекты удобны, когда нужно менять размер объекта (например, list, dict). Неизменяемые используются, когда важно гарантировать постоянство объекта.
- «Изменение» неизменяемых объектов принципиально дорого, так как требует создания копии. Изменение изменяемых объектов — дёшево.

### Как объекты передаются в функции

Важно понимать разницу между изменяемыми и неизменяемыми типами и то, как они ведут себя при передаче в функции. Правильный выбор типов существенно влияет на эффективность использования памяти.

Например, если изменяемый объект передаётся в функцию по ссылке, функция может изменить исходную переменную.

Чтобы этого избежать, исходную переменную нужно скопировать в другую переменную. Неизменяемые объекты можно передавать по ссылке, поскольку их значение всё равно не изменится.

## Способы выполнения кода Python: exec, eval, ast, code, codeop и др.

Метод `exec(object, globals, locals)` выполняет динамически созданную программу — строку или объект кода. Возвращает `None`. Важен только побочный эффект!

Пример 1:
```python
program = 'a = 5\nb=10\nprint("Sum =", a+b)'
exec(program)
```
```bash
Sum = 15
```

Пример 2:
```python
globals_parameter = {'__builtins__' : None}
locals_parameter = {'print': print, 'dir': dir}
exec('print(dir())', globals_parameter, locals_parameter)
```
```bash
['dir', 'print']
```

Метод `eval(expression, globals=None, locals=None)` разбирает и вычисляет переданное Python-выражение. Возвращает результат выражения!

```python
>>> a = 5
>>> eval('37 + a')   # это выражение
42
>>> exec('37 + a')   # это оператор-выражение; значение игнорируется (возвращается None)
>>> exec('a = 47')   # изменяет глобальную переменную как побочный эффект
>>> a
47
>>> eval('a = 47')  # нельзя вычислить оператор
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
  File "<string>", line 1
    a = 47
      ^
SyntaxError: invalid syntax
```

Если в `exec` или `eval` передаётся объект `code` (содержащий байткод Python), они ведут себя идентично, за исключением того, что `exec` игнорирует возвращаемое значение и всегда возвращает `None`. Поэтому можно использовать `eval` для выполнения кода с операторами, если предварительно скомпилировать его в байткод:
```python
>>> eval(compile('if 1: print("Hello")', '<string>', 'exec'))
Hello
>>>
```

`Abstract Syntax Trees` (AST) — мощная возможность Python. Можно писать программы, которые инспектируют и изменяют Python-код после разбора синтаксиса, но до компиляции в байткод.

Помимо компиляции в байткод, `compile` поддерживает компиляцию абстрактных синтаксических деревьев в объекты `code` и исходного кода в AST (функция `ast.parse` написана на Python и просто вызывает `compile(source, filename, mode, PyCF_ONLY_AST)`). Это используется, например, для динамического изменения исходного кода и создания кода на лету.

Модуль `code` предоставляет средства для реализации REPL (read-eval-print loop) в Python. Включает два класса и вспомогательные функции для создания приложений с **интерактивной командной строкой интерпретатора**.

Модуль `codeop` предоставляет утилиты для эмуляции Python REPL. Как правило, вы не будете использовать его напрямую — для включения такого цикла в программу лучше использовать модуль `code`.

## Ключевые отличия Python 2.x и 3.x

### Оператор деления
При переносе кода или выполнении кода Python 3.x в Python 2.x незамеченное изменение поведения целочисленного деления может быть опасным (ошибка не возникает). Рекомендуется использовать числа с плавающей точкой (например, 7.0/5 или 7/5.0) для получения ожидаемого результата.

### Функция `print`
Самое известное изменение. Ключевое слово `print` из Python 2.x заменено функцией `print()` в Python 3.x. Однако скобки работают и в Python 2, если после ключевого слова `print` добавить пробел — интерпретатор воспринимает это как выражение.

### Unicode
В Python 2 неявный тип `str` — ASCII. В Python 3.x неявный тип `str` — Unicode.

### `xrange`
`xrange()` из Python 2.x не существует в Python 3.x. В Python 2.x `range` возвращает список (range(3) → [0, 1, 2]), а `xrange` — объект xrange, работающий аналогично Java-итератору и генерирующий числа по мере необходимости.

### Обработка ошибок
Небольшое изменение в обработке ошибок: в Python 3.x обязательно ключевое слово `as`.

### Модуль `_future_`
Модуль `__future__` помогает мигрировать на Python 3.x. Если нужна поддержка Python 3.x в коде Python 2.x, можно использовать импорты из `_future_`.

### Six
Six — библиотека совместимости Python 2 и 3. Предоставляет вспомогательные функции для сглаживания различий между версиями Python с целью написания кода, совместимого с обеими версиями.

## `deepcopy`, метод `copy`, срезы и др.

`copy()` возвращает поверхностную копию списка, `deepcopy()` — глубокую копию.
Функция `slice()` в Python возвращает объект среза.

Срез можно применять к любой последовательности объектов (`string`, `bytes`, `tuple`, `list`, `range`) или к объекту, реализующему методы `__getitem__()` и `__len__()`.

## OrderedDict, DefaultDict

`OrderedDict` — подкласс словаря, запоминающий порядок вставки ключей.

**Важное замечание для Python 3.7+:** Начиная с Python 3.7, обычные объекты `dict` гарантированно сохраняют порядок вставки как часть спецификации языка. Тем не менее `OrderedDict` предоставляет дополнительные возможности:

| Возможность | `dict` | `OrderedDict` |
|-------------|--------|---------------|
| Сравнение на равенство | Не зависит от порядка | Зависит от порядка (два OrderedDict с одинаковыми элементами, но в разном порядке — не равны) |
| `move_to_end(key, last=True/False)` | Недоступно | Перемещает ключ в начало или конец |
| `popitem(last=True/False)` | Только с конца (LIFO) | С любого конца (LIFO или FIFO) |
| Использование памяти | Меньше | Больше |
| Производительность переупорядочивания | Не оптимизирована | Оптимизирована для частого переупорядочивания |

Используйте `OrderedDict`, когда нужно сравнение с учётом порядка, `move_to_end()` или двунаправленный `popitem()`.

`Defaultdict` — контейнер из модуля `collections`, подкласс словаря, который никогда не вызывает `KeyError`. Для несуществующего ключа он предоставляет значение по умолчанию.

```python
from collections import defaultdict

def def_value():
    return "Not Present"

d = defaultdict(def_value)
```

## Хешируемые объекты

Объект является хешируемым, если у него есть хеш-значение, не изменяющееся на протяжении всего его жизненного цикла. В Python есть встроенная функция `hash()`, а объекты реализуют хеширование через метод `__hash__()`. Для сравнения нужен метод `__eq__()` (примечание: `__cmp__()` удалён в Python 3). Хешируемые объекты, равные между собой, должны иметь одинаковое хеш-значение.

**Примечание:** встроенной функции `hashable()` в Python нет. Проверить хешируемость объекта можно так:
```python
from collections.abc import Hashable
isinstance(obj, Hashable)  # Возвращает True, если объект хешируем
# или просто:
try:
    hash(obj)
    print("Hashable")
except TypeError:
    print("Not hashable")
```

Все неизменяемые встроенные объекты Python хешируемы (int, str, tuple, frozenset), тогда как изменяемые контейнеры (list, dict, set) — нет.

`lambda` и пользовательские функции хешируемы (хешируются по идентификатору).

Объекты, хешированные через `hash()`, дают необратимые значения (односторонняя функция).
`hash()` вызывает `TypeError` для нехешируемых объектов, что можно использовать для проверки изменяемости.

## Сильная и слабая типизация

Python — язык с сильной динамической типизацией.

* **Сильная** типизация означает, что тип значения не меняется неожиданным образом. Строка, содержащая только цифры, магически не становится числом (как может случиться в Perl). Любое преобразование типа требует явного указания.
* **Динамическая** типизация означает, что тип есть у объекта во время выполнения, а не у переменной (как при статической типизации).

```python
bob = 1
bob = "bob"
```

Это работает, потому что переменная не имеет типа — она может ссылаться на любой объект. После `bob = 1` функция `type(bob)` вернёт `int`, а после `bob = "bob"` — `str`.

## Frozenset

Функция `frozenset()` возвращает неизменяемый объект frozenset, инициализированный элементами из переданного итерируемого объекта.

Frozenset — это просто неизменяемая версия `set`. В отличие от множества, элементы frozenset не могут быть изменены после создания.

Благодаря этому frozenset может использоваться как ключ словаря или как элемент другого множества. Однако, как и обычные множества, frozenset неупорядочен.

## Слабые ссылки

Python содержит модуль `weakref`, создающий слабую ссылку на объект. Если на объект нет сильных ссылок, сборщик мусора может освободить занятую им память.

Слабые ссылки используются для реализации кэшей и отображений, хранящих большие объёмы данных.

## Сырые строки (Raw strings)

Сырая строка в Python создаётся добавлением префикса `r` или `R` перед строковым литералом. Python воспринимает обратный слеш (`\`) в сырой строке как обычный символ. Это удобно, когда строка должна содержать обратные слеши без их интерпретации как управляющих последовательностей.

## Unicode и ASCII строки

Unicode — международный стандарт, поддерживающий отображение символов и уникальных чисел. Модуль Python `unicodedata` использует Unicode Character Database (UCD). Начиная с Python 3.13+, Python использует **Unicode 16.0.0** (выпущен в сентябре 2024), содержащий более 154 000 символов: разные письменности (английская, хинди, китайская, японская и др.), а также эмодзи. Каждый символ представлен кодовой точкой Unicode. Примеры: кодовая точка для «a» — U+0061, для эмодзи 🖐 — U+1F590, для Ω — U+03A9.

Главное в Python:
1. Python 2 использует тип `str` для байтов и тип `unicode` для кодовых точек. По умолчанию все строки — тип `str`, то есть байты. Кодировка по умолчанию — ASCII. Если входящий файл содержит кириллицу, Python 2 может завершиться с ошибкой, так как ASCII не обработает кириллические символы. В таком случае при чтении файлов нужно помнить о `decode("utf-8")`. Это неудобно.
2. Python 3 исправил это. Строки по-прежнему имеют тип `str`, но теперь они хранят кодовые точки Unicode — мы работаем с тем, что видим. Для сохранения строк в файлы используется тип `bytes`. Кодировка по умолчанию — UTF-8 вместо ASCII. Идеально!

## Pattern Matching (Python 3.10+)

Структурное сопоставление с образцом с помощью операторов `match` и `case` — мощная возможность, появившаяся в Python 3.10. Позволяет писать более элегантный и читаемый код при работе со сложными структурами данных.

### Ключевые возможности:

## GIL для каждого интерпретатора (Python 3.12+)

Функциональность Per-Interpreter GIL (PEP 684) позволяет добиться лучшего параллелизма, предоставляя отдельные GIL для разных интерпретаторов.

### Ключевые возможности:
- Каждый субинтерпретатор может иметь собственный GIL, что обеспечивает истинный параллелизм
- Субинтерпретаторы — «нечто среднее между потоками и процессами»
- Для работы с per-interpreter GIL модули расширений должны поддерживать многофазную инициализацию (PEP 489)

### Эволюция API:
- **Python 3.12**: Per-interpreter GIL доступен только через C-API
- **Python 3.13**: Базовый модуль `interpreters` (из `test.support`)
- **Python 3.14**: `InterpreterPoolExecutor` в `concurrent.futures` и полный модуль `interpreters` (PEP 734)

### Пример (Python 3.14+):
```python
from concurrent.futures import InterpreterPoolExecutor

def cpu_bound_task(n):
    return sum(i * i for i in range(n))

# У каждого интерпретатора свой GIL — истинный параллелизм!
with InterpreterPoolExecutor(max_workers=4) as executor:
    results = list(executor.map(cpu_bound_task, [10**6, 10**6, 10**6, 10**6]))
```

**Примечание:** Для Python 3.12-3.13 можно использовать `from test.support import interpreters` в целях тестирования, но это нестабильный публичный API.

## Free-Threaded Python (Python 3.13+, экспериментально)

Python 3.13 представил экспериментальный режим сборки без GIL (PEP 703), полностью отключающий GIL и позволяющий истинный многопоточный параллелизм.

### Ключевые возможности:
- **Без GIL:** потоки могут работать параллельно на нескольких ядрах CPU
- **Экспериментально:** доступно как отдельная опция сборки (`--disable-gil`)
- **Потокобезопасность:** использует мелкозернистые блокировки вместо GIL
- **Совместимость:** большинство чистого Python-кода работает; C-расширения могут потребовать обновления

### Использование:
```bash
# Установите free-threaded Python (например, через pyenv или официальные установщики)
python3.13t  # суффикс 't' означает free-threaded сборку

# Проверка, работает ли free-threaded сборка
import sys
print(sys._is_gil_enabled())  # False в free-threaded сборке
```

### Замечания о производительности:
- Однопоточная производительность может быть на 5-10% ниже (улучшено в Python 3.14)
- Многопоточные CPU-bound нагрузки могут дать значительный прирост скорости
- I/O-bound код выигрывает меньше (GIL и так снимался во время I/O)

## JIT-компилятор (Python 3.13+, экспериментально)

Python 3.13 добавил экспериментальный JIT-компилятор (PEP 744) на основе техники «copy-and-patch».

### Ключевые возможности:

- Скромный прирост производительности в первоначальном выпуске
- Ожидается значительное улучшение в будущих версиях
- Работает совместно с существующим специализирующим адаптивным интерпретатором (PEP 659)

## `partial`

`functools.partial(func, /, *args, **keywords)`

Возвращает новый объект `partial`, который при вызове ведёт себя как `func`, вызванная с позиционными аргументами `args` и именованными аргументами `keywords`. Если при вызове передаются дополнительные аргументы, они добавляются к `args`. Дополнительные именованные аргументы расширяют и переопределяют `keywords`.

## Лучшие практики написания декораторов

Основная идея — использовать функцию, возвращающую объект `partial` от самой себя, если она вызвана с параметрами до применения в качестве декоратора:

```python
from functools import wraps, partial

def decorator(func=None, parameter1=None, parameter2=None):

   if not func:
        # Единственный недостаток: для функций нет понятия "self" —
        # приходится полагаться на имя функции-декоратора в пространстве имён модуля
        return partial(decorator, parameter1=parameter1, parameter2=parameter2)
   @wraps(func)
   def wrapper(*args, **kwargs):
        # Код декоратора — parameter1 и т.д. можно использовать здесь свободно
        return func(*args, **kwargs)
   return wrapper
```
Декораторы, написанные по этому паттерну, можно применять к функции сразу без предварительного «вызова»:
```python
@decorator
def my_func():
    pass
```
Или с параметрами:

```python
@decorator(parameter1="example.com", ...):
def my_func():
    pass
```

# Области видимости в Python
## Правило LEGB

Python разрешает имена по правилу LEGB, названному по областям видимости Python. Буквы в LEGB означают: Local (локальная), Enclosing (объемлющая), Global (глобальная) и Built-in (встроенная):

1. **Local (локальная, функциональная)** — блок кода или тело любой функции Python или лямбда-выражения. Содержит имена, определённые внутри функции. Они видны только в коде этой функции. Создаётся при вызове функции, а не при её определении — разные вызовы создают разные локальные области видимости.

2. **Enclosing (объемлющая, нелокальная)** — специальная область, существующая только для вложенных функций. Если локальная область — это внутренняя вложенная функция, то объемлющая область — область видимости внешней (вмещающей) функции. Имена, определённые в объемлющей функции, видны как во внутренней, так и во внешней функции.

3. **Global (глобальная, модульная)** — самая верхняя область видимости в программе, скрипте или модуле Python. Содержит все имена, определённые на верхнем уровне программы или модуля. Видна из любой части кода. `dir()`

4. **Built-in (встроенная)** — специальная область видимости Python, создаваемая или загружаемая при запуске скрипта или открытии интерактивной сессии. Содержит ключевые слова, функции, исключения и другие встроенные атрибуты Python. Автоматически загружается при запуске программы. `dir(__builtins__)`: 152 имени

Правило LEGB — это процедура поиска имён, определяющая порядок, в котором Python ищет имена: сначала в локальной, затем в объемлющей, глобальной и встроенной областях. Если имя найдено, возвращается первое совпадение. Иначе — ошибка.

При вызове `dir()` без аргументов возвращается список имён в главной глобальной области видимости Python.

## `global` и `nonlocal`

### Оператор `global`

Оператор состоит из ключевого слова `global` и одного или нескольких имён через запятую. Все имена, перечисленные в операторе `global`, будут привязаны к глобальной (модульной) области видимости.

### Оператор `nonlocal`

Аналогично глобальным именам, нелокальные имена доступны из внутренних функций, но не могут быть присвоены или обновлены без оператора `nonlocal`. С помощью `nonlocal` можно определить список имён, которые будут трактоваться как нелокальные.

Оператор `nonlocal` состоит из ключевого слова `nonlocal` и одного или нескольких имён через запятую. Эти имена будут ссылаться на те же имена в объемлющей области видимости Python.

## Области видимости, вложенные функции и замыкания

Техника, при которой некоторые данные (в данном случае `hello`) «прикрепляются» к коду, называется замыканием (closure) в Python.

```python
def print_msg(msg):
    # Это внешняя вмещающая функция
    def printer():
        # Это вложенная функция
        print(msg)
    return printer  # возвращает вложенную функцию

# Вызовем эту функцию
another = print_msg("Hello")
another()
# Вывод: Hello
```

Условия создания замыкания в Python:

- Должна быть вложенная функция (функция внутри функции).
- Вложенная функция должна ссылаться на значение, определённое во вмещающей функции.
- Вмещающая функция должна возвращать вложенную функцию.

Декораторы Python активно используют замыкания.

## globals() и locals(): смысл и возможность изменения

- `globals()` всегда возвращает словарь пространства имён модуля
- `locals()` всегда возвращает словарь текущего пространства имён
- `vars()` возвращает словарь текущего пространства имён (если вызван без аргументов) или словарь аргумента

Словарь `locals()` не обновляется автоматически при присваивании переменных, а присваивание записей в этот словарь не изменяет соответствующие локальные переменные.

# ООП в Python

## SOLID

В программной инженерии SOLID — мнемонический акроним из пяти принципов проектирования, призванных сделать программные системы более понятными, гибкими и поддерживаемыми. Принципы — часть идей американского инженера-программиста Роберта Мартина, впервые представленных в его статье 2000 года «Принципы проектирования и паттерны проектирования».

Идеи SOLID:

- **Принцип единственной ответственности:** «У класса должна быть только одна причина для изменения». Иными словами, каждый класс должен иметь только одну ответственность.
- **Принцип открытости/закрытости:** «Программные сущности должны быть открыты для расширения, но закрыты для изменения».
- **Принцип подстановки Лисков:** «Функции, использующие указатели или ссылки на базовые классы, должны иметь возможность работать с объектами производных классов, не зная об этом».
- **Принцип разделения интерфейса:** «Лучше иметь много специализированных интерфейсов, чем один общий».
- **Принцип инверсии зависимостей:** «Зависеть от абстракций, а не от конкретных реализаций».

Акроним SOLID был введён позднее, около 2004 года, Майклом Фезерсом.

## Четыре основы ООП

- **Инкапсуляция** — объединение данных и функций, работающих с этими данными, в единую единицу — класс.

- **Абстракция** — работа с системой как с «чёрным ящиком»: не нужно понимать все внутренние детали, чтобы пользоваться системой.

- **Наследование** — класс, наследующий другой класс, автоматически получает его функциональность и свойства. Хорошая черта наследования — повторное использование кода: методы родительского класса не нужно переопределять в дочерних.

- **Полиморфизм** — поскольку производные объекты разделяют один интерфейс с родителями, вызывающий код может обращаться к любому методу этого интерфейса. Во время выполнения вызывается подходящий метод в зависимости от типа переданного объекта.

## Абстрактный базовый класс

Абстрактные базовые классы гарантируют, что производные классы реализуют методы и свойства, предписанные абстрактным базовым классом. Они разделяют интерфейс и реализацию, определяя обобщённые методы и свойства, которые должны использоваться в подклассах. Реализация — в конкретных подклассах, где можно создавать объекты, выполняющие задачи. Абстрактные базовые классы помогают избежать ошибок и упростить поддержку иерархий классов.

```python
       self._path = path
       self._file_name = file_name

    @abstractmethod

       pass
```

## getattr(), setattr()

Функция `hasattr(object, name)`:

Определяет, есть ли у объекта атрибут или метод с именем `name`. Возвращает `True`, если атрибут существует, и `False` в противном случае.

Функция `getattr(object, name[,default])`:

Получает атрибут или метод объекта. Если существует — выводит, если нет — выводит значение по умолчанию (опционально).

Функция `setattr(object, name, values)`:

Присваивает значение атрибуту объекта. Если атрибут не существует — создаёт его перед присваиванием.

## `__getattr__`, `__setattr__`, `__delattr__`

```python
>>> # Пример использования __setattr__ для динамического преобразования значения атрибута в верхний регистр
>>> class Frob:
...     def __setattr__(self, name, value):
...         self.__dict__[name] = value.upper()
...
>>> f = Frob()
>>> f.bamf = "bamf"
>>> f.bamf
'BAMF'
```

Обратите внимание: если атрибут найден через обычный механизм, `__getattr__()` не вызывается. (Это намеренная асимметрия между `__getattr__()` и `__setattr__()`.) Это сделано как из соображений эффективности, так и потому что иначе `__getattr__()` не имел бы возможности получить доступ к другим атрибутам экземпляра.

```python
>>> class Frob:
...     def __init__(self, bamf):
...         self.bamf = bamf
...     def __getattr__(self, name):
...         return 'Frob does not have `{}` attribute.'.format(str(name))
...
>>> f = Frob("bamf")
>>> f.bar
'Frob does not have `bar` attribute.'
>>> f.bamf
'bamf'
```

## `__getattribute__`

Если класс также определяет `__getattr__()`, последний не будет вызван, пока `__getattribute__()` явно не вызовет его или не вызовет `AttributeError`.

```python
>>> class Frob(object):
...     def __getattribute__(self, name):
...         print(f"getting `{name}`")
...         return object.__getattribute__(self, name)
...
>>> f = Frob()
>>> f.bamf = 10
>>> f.bamf
getting `bamf`
10
```

## Name mangling

В процессе name mangling любой идентификатор с двумя ведущими подчёркиваниями и не более чем одним завершающим подчёркиванием текстуально заменяется на `_classname__identifier`, где `classname` — имя текущего класса. Это означает, что идентификатор вида `__geek` заменяется на `_classname__geek`.

## @property (getter, setter, deleter)

```python
class Person:
    def __init__(self, name):
        self._name = name

    @property
    def name(self):
        print('Getting name')
        return self._name

    @name.setter
```

## Множественное наследование

Python знал как минимум три разных алгоритма MRO: классический, new-style Python 2.2 и new-style Python 2.3 (он же C3). Только последний сохранился в Python 3.

## Классический алгоритм

Классические классы использовали простую схему MRO: при поиске метода базовые классы обходились по простой схеме «глубина первым слева направо». Возвращался первый найденный объект. Например:
```python
class A:
  def save(self): pass

class B(A): pass

class C:
  def save(self): pass

class D(B, C): pass
```
При создании экземпляра `x` класса D классический MRO упорядочивал классы как D, B, A, C. Поэтому поиск метода `x.save()` давал `A.save()` (а не `C.save()`).

## Проблема ромба

Одна из проблем — поиск метода при «ромбовидном наследовании»:
```python
class A:
  def save(self): pass

class B(A): pass

class C(A):
  def save(self): pass

class D(B, C): pass
```
Здесь D наследует от B и C, оба из которых наследуют от A. При классическом MRO порядок обхода: D, B, A, C, A. Таким образом, `x.save()` вызовет `A.save()`. Однако это, скорее всего, не то, чего мы хотим: поскольку и B, и C наследуют от A, переопределённый метод `C.save()` является «более специализированным» и должен вызываться. Если `save()` используется для сохранения состояния объекта, пропуск `C.save()` нарушит работу программы.

Хотя такое множественное наследование было редким в существующем коде, new-style классы сделали его обычным явлением, поскольку все они наследовали от базового класса `object`. Таким образом, любое множественное наследование в new-style классах всегда создавало описанное выше ромбовидное отношение:
````python
class B(object): pass

class C(object):
  def __setattr__(self, name, value): pass

class D(B, C): pass
````

Для исправления MRO в Python 2.2 был принят подход, при котором MRO предварительно вычислялся при определении класса и сохранялся как атрибут объекта класса. Официально вычисление MRO документировалось как обход «глубина первым слева направо» с удалением всех дублирующихся классов, кроме последнего. Так для нашего примера порядок поиска: D, B, C, A (вместо D, B, A, C, A).

В Python 2.3 алгоритм MRO был заменён академически обоснованным алгоритмом C3. Одним из его следствий стало то, что Python теперь отвергает любую иерархию наследования с противоречивым порядком базовых классов.

**В Python MRO идёт снизу вверх и слева направо. Это означает: сначала метод ищется в классе объекта. Если не найден — в ближайшем суперклассе. При нескольких суперклассах поиск идёт слева направо, в порядке объявления разработчиком.**

- Нужно использовать одну конкретную возможность во множестве разных классов.

## type(), isinstance(), issubclass()

### Параметры `type()`
Функция `type()` принимает либо один параметр (объект), либо три параметра:

`name` — имя класса; становится атрибутом `__name__`

При передаче одного параметра — тип объекта.
При передаче трёх параметров — новый тип.

`isinstance()` возвращает `True`, если указанный объект является экземпляром указанного типа, иначе `False`. Если параметр типа — кортеж, функция вернёт `True`, если объект является одним из типов в кортеже.

`issubclass()` проверяет, является ли первый аргумент подклассом второго.

Синтаксис: `issubclass(class, classinfo)`

## `__slots__`

Специальный атрибут `__slots__` позволяет явно указать, какие атрибуты экземпляра ожидаются. Это даёт:

- более быстрый доступ к атрибутам
- экономию памяти

Экономия памяти достигается за счёт хранения значений атрибутов в слотах вместо `__dict__`.

Запрещается создание `__dict__` и `__weakref__`, если родительские классы также запрещают их и вы объявляете `__slots__`.

### Что профилировать?

Термин «профилирование» в основном используется для тестирования производительности с целью поиска узких мест. Для этого можно использовать инструменты трассировки: трассировка — это логирование информации о выполнении программы. Логирование метрик производительности — тоже способ анализа профилирования.

- Методы или функции (наиболее часто)
- Строки кода (аналогично профилированию методов, но построчно)

- Количество вызовов
- Профилирование методов и строк

### Детерминированное vs статистическое профилирование

При профилировании нужно следить за выполнением программы, что само по себе может влиять на производительность. Можно отслеживать все вызовы функций и события исключений (детерминированное профилирование) или использовать случайную выборку (статистическое профилирование). Детерминированное профилирование более точное, но создаёт дополнительные накладные расходы. Статистическое — менее точное, но с меньшими накладными расходами.

`cProfile` использует детерминированное профилирование. Пример статистического профилировщика с открытым исходным кодом — `pyinstrument`.

# Управление памятью в Python

## 3 поколения GC

Основной алгоритм сборки мусора в CPython — подсчёт ссылок. CPython подсчитывает, сколько мест ссылается на объект. Когда счётчик ссылок объекта достигает нуля, объект освобождается. Счётчик ссылок можно проверить с помощью `sys.getrefcount` (значение всегда на 1 больше, так как сама функция тоже хранит ссылку):
```python
x = object()
sys.getrefcount(x)
2
y = x
sys.getrefcount(x)
3
del y
sys.getrefcount(x)
2
```

Главная проблема подсчёта ссылок — он не справляется с циклическими ссылками:
```python
container = []
container.append(container)
sys.getrefcount(container)
3
del container
```

В этом примере `container` ссылается на себя, поэтому даже после удаления нашей ссылки счётчик никогда не достигнет 0. Именно для очистки таких циклических ссылок нужен циклический сборщик мусора (GC).

Для ограничения времени каждой сборки мусора GC использует оптимизацию — поколения. Идея основана на предположении, что большинство объектов живут очень недолго. На практике это подтверждается: в Python программах создаётся и уничтожается много временных объектов. Чем старше объект, тем меньше вероятность его недостижимости.

Все контейнерные объекты разбиты на три пространства/поколения. Каждый новый объект начинает в первом поколении (поколение 0). Если объект переживает сборку в своём поколении, он переходит в следующее (поколение 1), где проверяется реже. Если переживает и там (поколение 1) — переходит в последнее поколение (поколение 2), где проверяется наиболее редко.

Поколение собирается, когда число содержащихся в нём объектов достигает предопределённого порога. Пороги можно узнать с помощью `gc.get_threshold`:

### Модуль gc

```python
import gc
gc.get_threshold()
(700, 10, 10)
```
```python
>>> import gc
>>> gc.get_count()
(596, 2, 1)
```

Принудительно запустить сборку мусора можно методом `gc.collect()`:

```python
import gc
class MyObj:
    pass


# Переносим всё в последнее поколение для удобства проверки молодых поколений.

gc.collect()
0

# Создаём циклическую ссылку.

x = MyObj()
x.self = x

# Изначально объект находится в самом молодом поколении.

gc.get_objects(generation=0)
[..., <__main__.MyObj object at 0x7fbcc12a3400>, ...]

# После сборки мусора в молодом поколении объект переходит в следующее.

gc.collect(generation=0)
0
gc.get_objects(generation=0)
[]
gc.get_objects(generation=1)
[..., <__main__.MyObj object at 0x7fbcc12a3400>, ...]
```

Модуль GC предоставляет функцию `is_tracked(obj)`, возвращающую текущий статус отслеживания объекта.

### Какие объекты отслеживаются?

Для очистки циклических ссылок между объектами после их недостижимости необходим дополнительный механизм — циклический сборщик мусора (GC).

Как правило, экземпляры атомарных типов не отслеживаются, а экземпляры неатомарных (контейнеры, пользовательские объекты и др.) — отслеживаются. Однако для некоторых типов есть оптимизации, снижающие нагрузку GC:

- Кортежи, содержащие только неизменяемые объекты (целые числа, строки и рекурсивно — кортежи из неизменяемых), не нуждаются в отслеживании
- Словари, содержащие только неизменяемые объекты, также не нуждаются в отслеживании

## Рекомендации по использованию GC

Общее правило: не изменяйте поведение сборщика мусора.

## Утечки памяти и проблемы с деструкторами

Python, как и другие языки программирования, подвержен утечкам памяти. Утечки памяти в Python происходят, если сборщик мусора не очищает и не устраняет объекты без ссылок или неиспользуемые данные.

Разработчики Python стараются решить проблему утечек памяти путём добавления функций автоматического освобождения неиспользуемой памяти.

Однако некоторые объекты без ссылок могут пройти через сборщик мусора незамеченными, что приводит к утечкам.

# Потоки и многопроцессорность в Python
## GIL (определение, алгоритмы в 2.x и 3.x)

Механизм интерпретатора CPython, гарантирующий, что одновременно только один поток выполняет байткод Python. Это упрощает реализацию CPython, делая объектную модель (включая критические встроенные типы, такие как dict) неявно защищённой от конкурентного доступа. Блокировка всего интерпретатора упрощает его многопоточность за счёт параллелизма на многопроцессорных машинах.

Однако некоторые модули расширений — стандартные или сторонние — снимают GIL при выполнении вычислительно-интенсивных задач (сжатие, хеширование). GIL также всегда снимается при I/O-операциях.

```python
>>> import sys
>>> # В Python 2.x использовался sys.getcheckinterval() (удалён в Python 3.2)
>>> # Python 3.2+ использует переключение по времени вместо инструкций:
>>> sys.getswitchinterval()
0.005  # 5 миллисекунд — интервал переключения потоков
>>> sys.setswitchinterval(0.01)  # Можно настраивать при необходимости
```

**Примечание:** `sys.getcheckinterval()` и `sys.setcheckinterval()` удалены в Python 3.2. Старый подход проверял каждые N инструкций; новый использует интервал времени (по умолчанию 5 мс), что более справедливо и предсказуемо.

Проблема этого механизма: большую часть времени CPU-bound поток переполучал GIL раньше других потоков. Это было исследовано Дэвидом Бизли. Проблема была исправлена в Python 3.2 в 2009 году Антуаном Питру, добавившим механизм отслеживания числа неудачных попыток захвата GIL другими потоками и запрет текущему потоку перезахватывать GIL, пока другие потоки не получат возможность выполниться.

## Потоки (модули thread, threading; класс Queue; блокировки)

Простой вариант:
```python
from time import sleep, perf_counter
from threading import Thread

def task():
    print('Starting a task...')
    sleep(1)
    print('done')

start_time = perf_counter()

# создаём два новых потока
t1 = Thread(target=task)
t2 = Thread(target=task)

# запускаем потоки
t1.start()
t2.start()

# ждём завершения потоков
t1.join()
t2.join()

end_time = perf_counter()

print(f'It took {end_time- start_time: 0.2f} second(s) to complete.')
```

Лучше:

```python
from concurrent.futures import ThreadPoolExecutor
from time import sleep

def cube(x):
    result = x * x * x
    print(f'Куб числа {x}: {result}')
    return result

if __name__ == '__main__':
    values = [3, 4, 5, 6]

    with ThreadPoolExecutor(max_workers=5) as executor:
        # Используем map для применения функции cube ко всем значениям
        results = list(executor.map(cube, values))

    print("\nРезультаты:")
    for value, result in zip(values, results):
        print(f"Куб числа {value}: {result}")


```

Операции с `queue.Queue`:

- `maxsize` — максимальное количество элементов в очереди.
- `empty()` — возвращает True, если очередь пустая.
- `full()` — возвращает True, если в очереди maxsize элементов.
- `get()` — извлекает и возвращает элемент из очереди. Если очередь пустая — ждёт.
- `get_nowait()` — возвращает элемент, если он доступен немедленно, иначе вызывает QueueEmpty.
- `put(item)` — помещает элемент в очередь. Если очередь полная — ждёт свободного места.
- `put_nowait(item)` — помещает элемент без блокировки. Если мест нет — вызывает QueueFull.
- `qsize()` — возвращает количество элементов в очереди.

```python
from multiprocessing import Pool, cpu_count

def main():
```

```javascript
}
```
Делаем её совместимой с Python:

```javascript
#include <Python.h>

static PyObject *method_fputs(PyObject *self, PyObject *args) {
    char *str, *filename = NULL;
    int bytes_copied = -1;

    /* Разбираем аргументы */
    if(!PyArg_ParseTuple(args, "ss", &str, &filename)) {
        return NULL;
    }

    FILE *fp = fopen(filename, "w");
    bytes_copied = fputs(str, fp);
    fclose(fp);

    return PyLong_FromLong(bytes_copied);
}

static PyMethodDef FputsMethods[] = {
    {"fputs", method_fputs, METH_VARARGS, "Python interface for fputs C library function"},
    {NULL, NULL, 0, NULL}
};


static struct PyModuleDef fputsmodule = {
    PyModuleDef_HEAD_INIT,
    "fputs",
    "Python interface for the fputs C library function",
    -1,
    FputsMethods
};
```

## cffi, swig, SIP, boost-python

`cffi` — C Foreign Function Interface для Python. Взаимодействие практически с любым C-кодом из Python на основе C-подобных объявлений, которые зачастую можно скопировать из заголовочных файлов. https://cffi.readthedocs.io/en/latest/

```python
from cffi import FFI
ffibuilder = FFI()

# cdef() ожидает одну строку с объявлением C-типов, функций и
# глобальных переменных. Должна быть валидным C-синтаксисом.
ffibuilder.cdef("""
    float pi_approx(int n);
""")

# set_source() задаёт имя модуля расширения Python для создания
# и C-исходный код. Этот C-код должен делать объявленные функции,
# типы и глобальные переменные доступными — обычно это просто "#include".
ffibuilder.set_source("_pi_cffi",
"""
     #include "pi.h"   // заголовочный файл C-библиотеки
""",
     libraries=['piapprox'])   # имя библиотеки для линковщика

if __name__ == "__main__":
    ffibuilder.compile(verbose=True)
```

`SWIG` — компилятор интерфейсов, соединяющий программы на C и C++ со скриптовыми языками: Perl, Python, Ruby, Tcl. http://www.swig.org/exec.html

`SIP` — набор инструментов для лёгкого создания Python-привязок для библиотек C и C++. https://www.riverbankcomputing.com/static/Docs/sip/examples.html

### Boost

https://www.boost.org/doc/libs/1_78_0/libs/python/doc/html/tutorial/index.html

По традиции C/C++, начнём с «hello, world». Функция на C++:

```char const* greet()
{
   return "hello, world";
}
```
может быть открыта для Python с помощью обёртки Boost.Python:

```
#include <boost/python.hpp>

BOOST_PYTHON_MODULE(hello_ext)
{
    using namespace boost::python;
    def("greet", greet);
}
```

Всё. Готово. Теперь это можно собрать как разделяемую библиотеку. Итоговая DLL видна из Python:

```python
>>> import hello_ext
>>> print(hello_ext.greet())
hello, world
```
